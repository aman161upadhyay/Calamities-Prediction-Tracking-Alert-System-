# Critique procedure

1. Read the brief and identify the primary task.
2. Inspect supplied views at equal scales. Record viewport and state.
3. Review hierarchy, spacing, type, colour, interaction states, motion and copy separately.
4. Test the core task and accessibility floor only when authorized tools exist.
5. Classify findings as observed defect, accessibility concern, usability hypothesis or aesthetic preference.
6. Prioritize blocking task failures and false claims before decoration.
7. Return up to five priority findings. Include location, evidence, impact, severity, proposed change and validation method. Preserve specific strengths.
8. List unverified keyboard, screen reader, backend or performance behavior explicitly. After fixes, rerun affected checks and the core task.

Never infer functionality from appearance. Never invent participant feedback. If only a screenshot is available, deliver a visual review with explicit testing limits.
