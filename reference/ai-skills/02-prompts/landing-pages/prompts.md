# Three complete landing briefs

Purpose: build an evidence-safe page for a defined visitor. Supply actual commercial facts, assets, tokens, stack/version and CTA destination. These fictional practice examples adapt research 05. No conversion effect or local run is claimed.

## Developer tool

```text
Create a landing page for fictional Tracebench, which helps small backend teams
compare latency traces before deploying. Visitor: an engineer investigating a
regression. CTA: “Try the trace demo”. Use a real interactive comparison if data
is supplied; otherwise ask for approved traces. Do not invent production results.
Direction: technical instrument. White background, near-black reading text,
restrained cobalt action colour, licensed sans prose and monospace trace values.
Use compact navigation, left-aligned hero and readable trace comparison beside it.
Sections: concrete problem, trace demo, three workflow steps, supplied supported
integrations, privacy/storage answers, pricing link and final CTA.
No stock gradients, logo wall, identical benefit cards or fabricated statistics.
Use our existing shadcn/Radix stack and semantic tokens.
Deliver mobile layouts, accessible controls, loading/error states and
desktop/mobile screenshots. First propose tokens and hierarchy.
```

## Local craft studio

```text
Design booking for fictional Stillwater ceramics studio. Audience: adults
booking their first two-hour wheel class. Action: “View available classes”.
Request actual times, price, access information and rights-cleared photos.
Direction: tactile workshop journal. Derive a warm neutral from photography,
use readable dark ink, one muted blue action colour and licensed humanist sans.
Place a large photograph of hands shaping clay beside the class promise and
booking action, not behind text on busy imagery.
Structure: inclusions, beginner expectations, real dates, supplied instructor
details, access/cancellation answers and booking CTA.
Do not invent testimonials, scarcity counters or decorative handwritten copy.
On mobile put dates and price before long editorial material.
Include no-availability and booking-error states, reduced motion and keyboard
access. Propose tokens first. Report screenshots and actual checks.
```

## Operations service

```text
Build a focused page for fictional Northline, a maintenance scheduling service
for small apartment managers. Visitors need to know whether it fits their
contractor process. CTA: “Book a workflow call”.
Use supplied scope, regions, response commitments and approved case studies.
Direction: clear municipal wayfinding. Disciplined columns, navy text, white
surfaces and one accessible orange accent. Use a legible sans family.
Show request → assignment → confirmation only because it is the real sequence.
Order: service statement, workflow, eligibility/regions, approved case study
if available, scope/pricing terms, handoff/accountability objections and booking.
Keep a visible phone alternative if supplied.
No AI buzzwords, glass panels or false round-the-clock claims.
Deliver narrow-screen behavior and failed-booking recovery. First propose
tokens and hierarchy. Check keyboard, contrast and the actual CTA destination.
```

Acceptance: real facts only, readable demonstration, working CTA, recovery and responsive evidence. Failure modes: fabricated social proof, generic feature grids and hidden terms.
