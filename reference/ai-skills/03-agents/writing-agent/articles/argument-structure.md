# Build the argument

Start with Aman's thesis. "We should require production-shaped inputs in release tests" is an arguable position. A topic such as "the importance of evaluation" does not specify a decision.

| Part | Question to resolve | Failure to reject |
|---|---|---|
| Thesis | What does Aman claim, and within what scope? | A position inferred from his job title. |
| Stakes | Who pays a cost if the current practice continues? | Unsupported urgency. |
| Evidence | Which source supports each factual clause? | A number without denominator or method. |
| Mechanism | Why should the evidence change the reader's belief? | Correlation silently treated as cause. |
| Counterargument | When would a serious alternative be better? | An imaginary critic who is easy to dismiss. |
| Ending | What decision follows from the established argument? | A slogan or recap with no consequence. |

For a technical article, distinguish "the agent completed these tasks" from "the agent can replace engineers." The latter requires evidence beyond task completion.

[Graham](../../../06-reference-library/articles/graham-writes-and-write-nots.md) treats writing as a way to develop thought. Have Aman explain the claim aloud, then revise it when the evidence changes it. His [speech test](../../../06-reference-library/articles/graham-write-like-you-talk.md) helps identify prose that says less than it appears to.

[Orwell](../../../06-reference-library/articles/orwell-six-rules.md) supports concrete wording and visible agency. [Pinker](../../../06-reference-library/articles/pinker-source-of-bad-writing.md) explains why an expert may omit a logical step that a reader needs. Ask a fresh reader to reconstruct the argument from the draft alone.
