# Design rubric

Evaluate rendered behavior under the supplied task and device matrix. Source code alone cannot establish visual correctness.

| Criterion | PASS evidence | FAIL example |
|---|---|---|
| Main task, hard | Interaction and persisted result complete the brief. | A save toast appears without a stored change. |
| Access, hard | Required keyboard path, labels and specified accessibility checks pass. | A dialog traps focus with no exit. |
| Responsive content, hard | Required content remains available at each named viewport. | The only submit control is clipped on mobile. |
| Integrity, hard | Assets and evidence have rights; claims and records are approved. | Invented customer proof appears in the page. |
| Hierarchy, diagnostic | Screens and task observation show a clear next action. | Decoration competes with the operational table. |
| States and motion, diagnostic | Errors preserve input; reduced-motion paths retain information. | Failed save discards edits or animation hides content. |

Return locations as viewport, screen, control and interaction step. Record screenshot and behavior evidence separately. UNKNOWN applies when rendering or interaction is unavailable. A preferred aesthetic cannot cancel a task failure.
