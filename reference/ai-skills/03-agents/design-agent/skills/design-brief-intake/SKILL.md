# Intake procedure

1. Read the user's brief and existing tokens or component definitions.
2. Extract target user, usage context, job, primary action and observable completion event.
3. Record platform, supported widths, dependency versions, content schema, permissions, locale and performance budget.
4. Identify supplied proof, approved assets and their rights. Do not manufacture missing records or claims.
5. List loading, empty, no-results, denied, failure, success and task-specific edge states.
6. Ask only questions that materially alter truth, structure or authorization. Label reversible aesthetic assumptions.
7. Return a compact brief table, blocking questions, assumptions and access request. Do not build while a material blocker remains.

Acceptance: another implementer can identify what must work, which facts may appear and which actions require Aman. Hand off the accepted brief to uniqueness review.
