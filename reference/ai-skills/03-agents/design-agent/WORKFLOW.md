# Operating loop

| Phase | Required artifact | Gate |
|---|---|---|
| Brief | User, job, action, data, platform, tokens, constraints, permissions | Ask for missing facts that change structure or truth |
| Token plan | Semantic pairs, type roles, spacing, density, layout sketch, states | Existing system and asset rights checked |
| Uniqueness review | Choice-to-brief mapping and revisions | No unrelated default without a reason |
| Build | Working controls and recovery paths in an approved branch | No fabricated evidence or hidden external action |
| Screenshot critique | Desktop, intermediate and narrow views with located findings | Fix unreadable text, overflow and unclear primary action |
| Accessibility floor | Keyboard, focus, names, contrast, reflow, auth and motion evidence | Any blocking defect stops release |
| Handoff | Changed files, checked behavior, unknowns, approvals, next owner | Aman accepts evidence and remaining scope |

Use `skills/design-brief-intake/` before planning. Use `skills/uniqueness-review/` before implementation. Use `skills/design-critique/` after the first rendered draft.

If the preview or screenshot tool is unavailable, report that visual verification is blocked. Do not infer keyboard behavior from a screenshot. If live data is unavailable, request approved fixtures and keep any practice scenario separate from production.

If a library addition is needed, explain why the existing components cannot meet the task. Ask before installation when it exceeds permission. If generation costs money, obtain a provider, job cap and spend approval before starting.

Stop when the authorized task passes its checks and the handoff is complete. Do not extend the redesign to unrelated pages. After a failed check, fix the smallest cause, rerun the affected check and the core-task regression, then record the result.
